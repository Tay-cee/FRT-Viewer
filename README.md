# FRT-VIEWER: RCMP Firearms Reference Table Viewer

This project turns the RCMP **Firearms Reference Table (FRT) Report** PDF into a searchable
SQLite database, and comes with a Discord bot for looking records up.

- **`frt`** (C) imports the roughly 100,000-page report in about a minute. When a new report
  comes out, importing it applies only the differences and records what was added,
  changed or removed.
- **`bot/`** (Python, discord.py) has slash commands to look up FRNs, search, browse
  changes between reports, and attach images to records.

> **Not included:** the FRT report and the database built from it. The report is RCMP
> copyright and too large for Git. Get the PDF from the RCMP, put it in `frt-report/`, and
> import it (see [Quick start](#quick-start)).
>
> The FRT is an administrative document, not a legal instrument. The Criminal Code and its
> regulations are the legal authority on firearm classification. This project isn't
> affiliated with or endorsed by the RCMP.

## Quick start

    # Debian/Ubuntu: sudo apt install build-essential pkg-config libsqlite3-dev poppler-utils python3-venv
    # Arch/Artix:    sudo pacman -S base-devel sqlite poppler python
    make
    ./frt import frt-report/<report>.pdf       # builds frt.db
    ./frt search norinco sks

    cp bot/.env.example bot/.env               # add your bot token, see "Discord bot" below
    bot/run.sh

## Requirements

- gcc/cc, make, pkg-config
- SQLite 3 development library (`sqlite3.h`, `-lsqlite3`)
- poppler-utils (`pdftotext`, `pdfinfo`)
- For the bot: Python 3.10+

## Build and test

    make            # produces ./frt
    make test       # parser/importer tests against a synthetic report (tests/fixture.txt)
    make test-bot   # offline bot checks (needs discord.py)
    make install    # optional, installs to /usr/local/bin

The CI in `.github/workflows/ci.yml` runs all of these on every push. `tests/fixture.txt`
is made-up data in the report's layout, so the tests don't need the real PDF. It's
generated by `tests/make_fixture.py`. If you change the parser on purpose, regenerate the
expected output with `./frt parse tests/fixture.txt > tests/expected.txt`.

## Usage

    ./frt import frt-report/frt-1102.pdf     # ~1 min for the full 108k-page report
    ./frt import frt-report/frt-NEW.pdf      # later: applies only the differences

    ./frt show 87195                         # full record + change history
    ./frt search norinco jw                  # every word must match make/model/manufacturer/alias
    ./frt search --class prohibited --type rifle ar-15
    ./frt changes                            # what the latest report changed
    ./frt changes --report 2026/11/02 --kind modified
    ./frt reports                            # imported reports with add/modify/remove counts
    ./frt stats

The database is `./frt.db` by default. Use `--db FILE` (before the command) or `$FRT_DB`
to use a different one.

### Importing a new report

- The report date comes from the "Valid as of" date in the page header.
- If you import a report that's already in the database, it's skipped. If the database
  already has a newer report, an older one is refused. `--force` overrides both checks.
- Each FRN is compared section by section (summary, calibres, notes, cross-refs, aliases,
  year dates, importers) using content hashes:
  - **added**: FRN not seen before
  - **modified**: one `changes` row per changed summary field (old → new) and per changed
    section. Calibre-table changes keep the old and new table as text.
  - **removed**: FRN missing from the new report. The row stays, with `removed = 1`.
  - **restored**: a removed FRN that shows up again
- The first import is the baseline, so it doesn't log a change for every record.
- Each import runs in one transaction. If parsing fails, or the new report has fewer than
  half the records already in the database (which suggests a truncated PDF), nothing is
  changed.

## Discord bot (`bot/`)

A Python ([discord.py](https://discordpy.readthedocs.io)) front-end. It reads `frt.db`
directly and runs `./frt import` when a report needs importing.

### Setup

1. https://discord.com/developers/applications → **New Application** → **Bot** → **Reset Token**,
   and copy the token.
2. **OAuth2 → URL Generator**: tick scopes `bot` and `applications.commands`, and bot permissions
   `Send Messages` and `Embed Links`. Open the generated URL and add the bot to your server.
3. `cp bot/.env.example bot/.env`, then fill in `DISCORD_TOKEN` and `FRT_GUILD_ID` (with
   `FRT_GUILD_ID` set, commands show up right away).
4. `bot/run.sh` (creates `bot/.venv` and installs discord.py on the first run).

### Commands

| command | |
|---|---|
| `/frn query:` | Opens a record. Suggestions appear as you type an FRN, make, model or alias. Buttons switch between Summary (with any images), Calibres, Notes, Cross-refs, AKA/Importers and History. A drop-down on the Cross-refs page opens a linked FRN. |
| `/search text: make: manufacturer: classification: type:` | Paged results. `make` and `manufacturer` suggest values (with record counts) as you type. A drop-down on the results opens a record (and a button to go back to the results). |
| `/changes report: kind:` | What a report added, modified, removed or restored. |
| `/reports`, `/stats` | Imported reports and database totals, including how many firearms have images. |
| `/import file: force:` | Admins only. Imports a PDF from `frt-report/` (newest by default) and shows progress. |

`private:True` on `/frn` and `/search` makes the reply visible only to you. Only the person who ran a command can press its buttons.

### Images

Each FRN can have pictures. They appear on the record's **Summary** page, with the caption and
who added it. If there are several, the ◀ 📷 ▶ buttons on the Summary page flip through them.
Search results with pictures get a 📷 marker.
A record without pictures shows a "📷 No image yet" note on its Summary, asking anyone who has
a photo to add one.

| command | |
|---|---|
| `/image add frn: image: caption:` | Upload a PNG, JPEG, GIF or WebP (up to `FRT_IMAGE_MAX_MB`, default 8). |
| `/image view frn:` | Open a record's summary with its pictures. |
| `/image caption frn: image: caption:` | Change or clear a caption. |
| `/image remove frn: image:` | Delete an image (admins, or the person who added it). |

Who can add images is set by `FRT_IMAGE_UPLOADERS`: `admins` (the default) or `everyone`.

The images live in plain folders, so you can manage them without the bot:

    images/
      87195/
        20261112-021845-3cc6ff.png     <- uploaded through the bot (time-stamped name)
        left-side.jpg                  <- or just copy files in yourself
        captions.json                  <- captions / who added it (optional)

Images are shown in file-name order. To remove one, delete the file. The image folder is
separate from `frt.db`, so importing a new report never touches it, and images stay with
their FRN through every update.

### New reports

Put the new PDF in `frt-report/`, then either run `/import`, or set `FRT_AUTO_IMPORT=1` and
the bot imports any new PDF that has sat untouched for 2 minutes (it checks every
`FRT_WATCH_MINUTES`). If `FRT_ANNOUNCE_CHANNEL_ID` is set, the result and the first changes
are posted in that channel. The `./frt` command-line tool still works alongside the bot.

## Schema (main tables)

| table        | contents |
|--------------|----------|
| `firearms`   | one row per FRN: make, model, manufacturer, level, type, action, country, serial_numbering, legal_classification, report bookkeeping, `removed` flag |
| `calibres`   | calibre/shots/barrel rows: `sub` (the "- n" number), calibre, shots, barrel_mm, legal_classification, legal_authority, level, barrel_type_code |
| `notes`      | one row per bullet: category (Make, Model, Serial Number, …), text |
| `cross_refs` | ref_frn, make, model, manufacturer, type, action |
| `aliases`, `year_dates`, `importers` | list sections |
| `reports`    | each imported report |
| `changes`    | change log per report |
| `firearm_calibres` (view) | active firearms joined with their calibre rows |

You can also query it directly with SQL:

    sqlite3 frt.db "SELECT frn, make, model, calibre, shots, barrel_mm FROM firearm_calibres
                    WHERE row_class = 'Non-Restricted' AND calibre LIKE '%308%' LIMIT 20"

## How it works

1. `pdfinfo` gets the page count. The PDF is split into 500-page chunks, and several
   `pdftotext -fixed 3` processes run at once (one per CPU, up to 16).
   Fixed-pitch mode makes the text column match the x-position on the page, so table columns
   line up the same way on every page. That matters when a table continues onto the next page
   without its header.
2. `src/parse.c` reads the chunks in page order. A new record starts whenever the FRN in the
   page header changes, and records can span several pages. Table rows are mapped to columns
   using the column positions from the table header.
3. `src/db.c` hashes each record and adds or updates it in SQLite.

For debugging: `pdftotext -fixed 3 -f A -l B report.pdf x.txt && ./frt parse x.txt` prints
the parsed records. `frt import x.txt` also accepts that text format.
